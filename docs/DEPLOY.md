# פריסה: איך זה עולה לאוויר בחינם

שלוש חתיכות, שלושה שירותים, אפס עלות:

| חתיכה | שירות | שכבה חינמית |
|---|---|---|
| **האתר** (`/`, `/download`, `/transparency`, `/privacy`) | Vercel | חינמי, CDN, HTTPS ודומיין |
| **האפליקציה** (`/app` + `/api/*`) | Render | שירות חינמי, 750 שעות בחודש |
| **מסד הנתונים** | Turso | SQLite מנוהל, שכבה חינמית שאינה פגה |

## למה דווקא ככה

לשירות חינמי אין דיסק מתמיד - לא ב-Render, לא ב-Koyeb ולא ב-Cloud Run. ב-Fly.io אין
יותר שכבה חינמית בכלל, וב-Railway הקרדיט החינמי לא מספיק לשירות שרץ כל הזמן.
לכן מסד הנתונים לא יכול להיות קובץ על הדיסק של השרת.

**Turso פותר את זה בלי לשנות את ה-SQL:** הוא SQLite מנוהל. אותן מיגרציות, אותן שאילתות,
אותם placeholders. מה שהוחלף זה הדרייבר בלבד - `src/db/driver-turso.ts` במקום
`src/db/driver-sqlite.ts`. הרצה מקומית ממשיכה לעבוד עם קובץ, וכל 119 הבדיקות
רצות על הדרייבר המקומי.

---

## שלב 1: מסד הנתונים ב-Turso

1. **turso.tech** ← הרשמה (אימייל בלבד, בלי כרטיס אשראי).
2. יצירת מסד נתונים חדש. לבחור אזור קרוב (אירופה).
3. להעתיק שני דברים:
   - **Database URL** - בצורה `libsql://<db>-<org>.turso.io`
   - **Auth token** - נוצר בלוח הבקרה תחת המסד
4. זה הכול. הטבלאות נוצרות לבד: המיגרציות רצות אוטומטית בעלייה הראשונה של השרת.

השכבה החינמית: 5GB אחסון, 500 מיליון קריאות שורה בחודש, והמסד נשאר ער.
האפליקציה הזו רחוקה מאוד מהגבולות האלה.

## שלב 2: האפליקציה ב-Render

1. **render.com** ← New ← **Blueprint** ← לבחור את המאגר.
   Render קורא את `render.yaml` ומגדיר שירות Docker חינמי לפי התצורה שבו.
2. להגדיר את משתני הסביבה הסודיים (Environment ← Add):

   ```
   TURSO_DATABASE_URL=libsql://<db>-<org>.turso.io
   TURSO_AUTH_TOKEN=<הטוקן מ-Turso>
   SESSION_SECRET=<32 בתים אקראיים>
   ACCESS_CODE=<קוד הכניסה המהירה>
   SEED_ADMIN_EMAIL=<האימייל שלך>
   SEED_ADMIN_PASSWORD=<סיסמה חזקה, 10 תווים לפחות>
   ```

   ליצירת הסוד:
   `node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"`

3. Deploy. בעלייה הראשונה: המיגרציות רצות ב-Turso, ונוצר חשבון המנהל.
4. **להתחבר ולשנות את סיסמת המנהל מיד.**

### חשבון המנהל נוצר לבד - וזה בכוונה
בתוכנית החינמית של Render אין גישת shell, ולכן אי אפשר להריץ שם `npm run seed`.
השרת יוצר את חשבון המנהל בעלייה הראשונה, רק אם `SEED_ADMIN_EMAIL` ו-
`SEED_ADMIN_PASSWORD` מוגדרים **ואין עוד שום חשבון מנהל**. אחרי זה הפעולה לא חוזרת.

### מה שצריך לדעת על התוכנית החינמית
- **השירות נרדם אחרי 15 דקות** בלי תנועה. הכניסה הראשונה אחרי שינה לוקחת
  בדרך כלל חצי דקה עד דקה. אחרי זה הכול מהיר.
- **750 שעות בחודש** - מספיק לשירות אחד שרץ כל הזמן.
- **עותק אחד.** מגבלת הקצב שמורה בזיכרון התהליך, ולכן ריבוי עותקים היה שובר אותה.
- אם ההרדמות מפריעה: שירות בתשלום הוא כ-7$ לחודש. **אין צורך בדיסק** בתשלום,
  כי הנתונים ב-Turso.

## שלב 3: האתר ב-Vercel

**האתר פרוס:** https://personal-coach-beige.vercel.app
(כתובת נוספת לאותה פריסה: `personal-coach-amifri.vercel.app`)

הפרויקט: `personal-coach`, פריסת ייצור מ-`main`, Node 24.x, הבנייה
`node --no-warnings scripts/build-site.ts` והתוצר `dist-site/`. אין תלויות להתקין.
הגנת ההתחברות (SSO Protection) כובתה כדי שהאתר יהיה פתוח למבקרים.

**הפרויקט לא מחובר ל-GitHub כחיבור קבוע** - הפריסה נוצרה דרך ה-API מתוך
`engamifriberg-a11y/personal-coach`. לכן דחיפה ל-`main` לא פורסת מחדש לבד.
לחיבור קבוע: Vercel ← הפרויקט ← Settings ← Git ← Connect Git Repository.

**משתנה סביבה אחד שנשאר להגדיר**, אחרי שהאפליקציה תעלה ב-Render:
```
APP_URL=https://<שם-השירות>.onrender.com
```
בזמן הבנייה כל כפתורי "פתיחת האפליקציה" באתר יוצבעו לשם. בלי `APP_URL`,
הנתיב `/app` מציג עמוד שמסביר שהאפליקציה רצה בנפרד - במקום קישור שבור.
זה המצב כרגע.

### דומיין משלכם (אופציונלי)
- `example.co.il` ו-`www` → Vercel (ייתן את רשומות ה-DNS).
- `app.example.co.il` → CNAME לכתובת של Render, ואז `APP_URL=https://app.example.co.il`.

## אימות אחרי פריסה

**הבדיקה הראשונה שחייבת לעבור** - החיבור למסד:

```
curl -s https://<השירות>.onrender.com/api/health/db
```

תשובה טובה: `{"ok":true,"driver":"turso","detailHe":"המסד מגיב (turso)"}`
תשובה `503` עם `"ok":false` אומרת שה-URL או הטוקן של Turso שגויים. בלוג של Render
יופיע הפירוט.

ואחר כך:

```
curl -s https://<השירות>.onrender.com/api/site-info        # JSON עם מספר התרגילים
curl -s -o /dev/null -w '%{http_code}\n' https://<השירות>.onrender.com/app   # 200
```

ובדפדפן:
1. `/` באתר ב-Vercel - נטען, שורת הזכויות בתחתית, כפתור "פתיחת האפליקציה" מוביל ל-Render.
2. `/app` - מסך הכניסה. כניסה מהירה עם שם וקוד.
3. השלמת השאלון ← קבלת תוכנית ← התחלת אימון ← שמירת סט.
4. **פריסה מחדש ב-Render, ואז התחברות שוב.** אם הנתונים שם - Turso עובד והנתונים
   שרדו. זו הבדיקה שבאמת חשובה.
5. התקנה על הטלפון מהכתובת של Render (יש HTTPS, זה עובד).

## מה נבדק ומה לא

| מה | מצב |
|---|---|
| הרצה עם משתני הסביבה של ייצור | ✅ נבדק |
| הגשת האתר, האפליקציה וה-API מאותו שרת | ✅ 119 בדיקות |
| **דרייבר Turso: פרמטרים, שורות, batch אטומי, שגיאות, טוקן שגוי, timeout** | ✅ נבדק מול מימוש מקומי של פרוטוקול ה-HTTP שלו |
| שקילות בין הדרייברים: אותן מיגרציות, אותה סכמה, אותו מסלול repository | ✅ נבדק |
| בניית האתר הסטטי, עם וללא `APP_URL` | ✅ נבדק |
| **התנהגות שירות Turso המנוהל בפועל** | ⚠️ לא נבדק - אין גישה לשירות מסביבת הפיתוח |
| בניית תמונת ה-Docker | ⚠️ לא נבדקה - לא היה daemon של Docker |
| **פריסת האתר ב-Vercel** | ✅ בוצעה - הבנייה הצליחה והפריסה במצב READY |
| **תוכן הדפים בכתובת החיה** | ⚠️ לא אומת מכאן - הסביבה הזו חוסמת פניות לכתובת. התוכן זהה ל-`dist-site/` שנבנה ונבדק מקומית |
| פריסת האפליקציה (Render) ומסד הנתונים (Turso) | ⚠️ לא בוצעו - דורשות הרשמה שלך |

הפרוטוקול של Turso מכוסה על ידי שרת מקומי שמדמה אותו (`tests/fake-turso.ts`),
כולל מקרי שגיאה. הבדיקה הזו גם תפסה באג אמיתי: ב-pipeline רגיל פקודה שנכשלת
אינה עוצרת את ה-COMMIT שאחריה, ולכן `batch` עבר לשימוש בסוג הבקשה `batch`
עם תנאים בין השלבים. בלי זה, מחיקת חשבון שנכשלת באמצע הייתה משאירה חשבון חצי מחוק.

אם `/api/health/db` נכשל בפריסה, כל השאר לא רלוונטי - שם מתחילים לבדוק.

## מסלולים אחרים, אם המצב משתנה

**שרת עם דיסק מתמיד** (Railway כ-5$ לחודש, Render בתשלום, מכונה וירטואלית):
`DB_DRIVER=sqlite` ו-`SQLITE_PATH=/data/coach.db`, עם volume ממופה ל-`/data`.
אפס שינוי בקוד - זה בדיוק מה שהדרייבר המקומי עושה. `railway.json` כבר מוגדר לכך.

**הכול על מארח אחד:** השרת מגיש גם את האתר וגם את האפליקציה, ולכן אפשר לדלג
על Vercel ולהשתמש בכתובת אחת. אין CORS ואין שתי פריסות לתחזק.

**מכונה חינמית לתמיד:** Oracle Cloud Always Free נותן מכונה שנשארת דלוקה עם דיסק
אמיתי. בתמורה אתם מתחזקים שרת Linux, והמכונה עשויה להיות מוחזרת אם היא יושבת
בלי שימוש.

## גיבוי

ב-Turso יש snapshots מתוך השירות. בנוסף, ייצוא ידני:

```
curl -s https://<השירות>/api/account/export -H "cookie: <סשן>" > backup.json
```

זה מייצא נתוני משתמש אחד. לגיבוי מלא של המסד כדאי להשתמש בכלי של Turso.
מסד נתונים של בריאות שנמחק הוא לא תקלה שמתאוששים ממנה בהתנצלות.

## לפני שמכניסים אנשים אמיתיים

`docs/STATUS.md` מפרט במלואו. בקצרה, מה שחוסם:

1. ביקורת מקצועית על 11 כללי בטיחות ותזונה ועל 57 התרגילים.
2. תנאי שימוש ומדיניות פרטיות שנכתבו על ידי עורך דין.
3. כיבוי הכניסה המהירה (`QUICK_ACCESS=off`) ומעבר לחשבונות מאומתים -
   קוד משותף אינו הוכחת זהות.
4. אימות אימייל ואיפוס סיסמה.
5. גיבויים וניטור.
