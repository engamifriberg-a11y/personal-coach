# פריסה: איך זה עולה לאוויר בחינם

שתי חתיכות, שני שירותים, אפס עלות:

| חתיכה | שירות | שכבה חינמית |
|---|---|---|
| **האתר והאפליקציה** (`/`, `/app`, `/api/*`) | Vercel | CDN, HTTPS, דומיין, פונקציות |
| **מסד הנתונים** | Turso | SQLite מנוהל, שכבה חינמית שאינה פגה |

**האתר חי:** https://personal-coach-beige.vercel.app
(כתובת נוספת לאותה פריסה: `personal-coach-amifri.vercel.app`)

## למה דווקא ככה

**מסד הנתונים לא יכול להיות קובץ על הדיסק.** לשירות חינמי אין דיסק מתמיד - לא
ב-Render, לא ב-Koyeb ולא ב-Cloud Run. ב-Fly.io אין יותר שכבה חינמית בכלל,
וב-Railway הקרדיט החינמי לא מספיק לשירות שרץ כל הזמן.

**Turso פותר את זה בלי לשנות את ה-SQL:** הוא SQLite מנוהל. אותן מיגרציות, אותן
שאילתות, אותם placeholders. מה שהוחלף זה הדרייבר בלבד - `src/db/driver-turso.ts`
במקום `src/db/driver-sqlite.ts`. הרצה מקומית ממשיכה לעבוד עם קובץ, וכל הבדיקות
רצות על הדרייבר המקומי.

**והאפליקציה עצמה רצה על Vercel, לא על שרת נפרד.** המסלול הראשון היה Render, והוא
עבד - אבל דרש חשבון שני, כתובת שנייה (ולכן CORS), והשירות החינמי שם נרדם אחרי
15 דקות. אותו קוד שרת בדיוק רץ עכשיו כפונקציה על Vercel, באותו דומיין של האתר:

```
src/server/index.ts   handleRequest(req, res)  - אותו טיפול בבקשה
api/[...path].ts      export default handleRequest  - חיבור בלבד, אפס לוגיקה
```

`createApp()` עדיין עוטף את אותו `handleRequest` ב-`node:http`, ולכן ההרצה
המקומית, תמונת ה-Docker והבדיקות לא השתנו. אין גרסה שנייה של השרת לתחזק.

### מה שהמעבר הזה חייב לשנות בקוד
**המיגרציות נארזות למודול.** קודם הן נקראו מהדיסק (`readdirSync` על
`src/db/migrations/`). באריזה לפונקציה הקוד הופך לקובץ אחד, והתיקייה הזו אינה
קיימת לידו - המסד היה עולה בלי סכמה, בשקט. לכן `scripts/build-migrations.ts`
מייצר את `src/db/migrations.generated.ts`, ואין יותר קריאת דיסק בזמן ריצה.
קובצי ה-`.sql` נשארים המקור האמיתי, ו-`tests/migrations-generated.test.ts`
נכשל אם ערכו אותם ושכחו להריץ `npm run build:migrations`.

**SQLite נפסל במפורש באירוח הזה.** `describeDbConfig()` מחזיר "לא מוכן" כש-
`DB_DRIVER=sqlite` ומשתנה הסביבה `VERCEL` מוגדר. קובץ SQLite שם היה נראה עובד
ומאבד כל נתון בכל הפעלה. עדיף להיכשל בגלוי.

## שלב 1: מסד הנתונים ב-Turso

1. **turso.tech** ← Sign Up ← התחברות עם GitHub. בלי כרטיס אשראי.
2. **Create Database** ← שם, למשל `coach`. אזור קרוב (אירופה).
3. אחרי היצירה מוצגים פרטי החיבור. להעתיק שניים:
   - **Database URL** - בצורה `libsql://<db>-<org>.turso.io`
   - **Auth token** - באותו מסך: Get Token ← Generate Token
4. זה הכול. הטבלאות נוצרות לבד: המיגרציות רצות בבקשה הראשונה.

השכבה החינמית: 9GB אחסון, 500 מסדים, והמסד נשאר ער.
האפליקציה הזו רחוקה מאוד מהגבולות האלה.

## שלב 2: משתני הסביבה ב-Vercel

Vercel ← הפרויקט `personal-coach` ← Settings ← Environment Variables.

| משתנה | ערך | מצב |
|---|---|---|
| `DB_DRIVER` | `turso` | ✅ מוגדר |
| `SESSION_SECRET` | 32 בתים אקראיים | ✅ מוגדר |
| `ACCESS_CODE` | קוד הכניסה המהירה | ✅ מוגדר |
| `NODE_ENV` | `production` | ✅ מוגדר |
| `TRUST_PROXY` | `1` | ✅ מוגדר |
| `TURSO_DATABASE_URL` | מ-Turso | ⬜ נדרש |
| `TURSO_AUTH_TOKEN` | מ-Turso | ⬜ נדרש |
| `SEED_ADMIN_EMAIL` | האימייל שלכם | ⬜ אופציונלי |
| `SEED_ADMIN_PASSWORD` | סיסמה חזקה, 10 תווים לפחות | ⬜ אופציונלי |

ליצירת סוד: `node -e "console.log(require('crypto').randomBytes(32).toString('base64url'))"`

אחרי הוספת משתנה צריך **פריסה מחדש** - משתני סביבה נקראים בזמן הפעלת הפונקציה,
והפריסה הקיימת לא תראה אותם.

### חשבון המנהל נוצר לבד - וזה בכוונה
באירוח חסר-מצב אין עלייה מסודרת ואין shell להריץ `npm run seed`. השרת יוצר את
חשבון המנהל בבקשה הראשונה, רק אם `SEED_ADMIN_EMAIL` ו-`SEED_ADMIN_PASSWORD`
מוגדרים **ואין עוד שום חשבון מנהל**. אחרי זה הפעולה לא חוזרת.
**להתחבר ולשנות את הסיסמה מיד.**

## שלב 3: פריסה

הפרויקט `personal-coach` (`prj_YvXdsAPMQl8tLo06tBDauXVusB3G`), Node 24.x,
בנייה `npm run build:site`, תוצר `dist-site/`. `vercel.json` קובע את השאר:
`cleanUrls` (ולכן `app.html` מוגש ב-`/app`), כותרות אבטחה ו-CSP.

**הפרויקט אינו מחובר ל-Git כחיבור קבוע** - הפריסות נוצרו דרך ה-API מתוך
`engamifriberg-a11y/personal-coach`, ולכן דחיפה ל-`main` אינה פורסת מחדש לבד.
לחיבור קבוע: Settings ← Git ← Connect Git Repository.

**הגנת ההתחברות (SSO Protection) דולקת כברירת מחדל** בפרויקט חדש וחוסמת כל מבקר.
כאן היא כבויה.

### דומיין משלכם (אופציונלי)
`example.co.il` ו-`www` → Vercel, שייתן את רשומות ה-DNS. כלום מעבר לזה:
האתר, האפליקציה וה-API על אותו דומיין.

## אימות אחרי פריסה

**הבדיקה הראשונה שחייבת לעבור** - החיבור למסד:

```
curl -s https://personal-coach-beige.vercel.app/api/health/db
```

- `{"ok":true,"driver":"turso",...}` - הכול מחובר.
- `503` עם `"missing":["TURSO_DATABASE_URL",...]` - המשתנים טרם הוגדרו, או שהוגדרו
  בלי פריסה מחדש אחריהם.
- `503` עם `"ok":false` ו-`driver:"turso"` אחרי שהוגדרו - ה-URL או הטוקן שגויים.
- עמוד הבית של האתר במקום JSON - הפונקציה לא נבנתה. שם מתחילים לבדוק.

ואחר כך:

```
curl -s https://personal-coach-beige.vercel.app/api/site-info    # JSON עם מספר התרגילים
curl -s -o /dev/null -w '%{http_code}\n' https://personal-coach-beige.vercel.app/app   # 200
```

ובדפדפן:
1. `/` - נטען, שורת הזכויות בתחתית, "פתיחת האפליקציה" מוביל ל-`/app`.
2. `/app` - לפני שהמסד חובר: מסך "האפליקציה כמעט מוכנה" שמסביר מה חסר.
   אחרי שחובר: מסך הכניסה. כניסה מהירה עם שם וקוד.
3. השלמת השאלון ← קבלת תוכנית ← התחלת אימון ← שמירת סט.
4. **פריסה מחדש, ואז התחברות שוב.** אם הנתונים שם - Turso עובד והנתונים שרדו.
   זו הבדיקה שבאמת חשובה, כי לפונקציה אין שום אחסון מקומי.
5. התקנה על הטלפון מ-`/app` (יש HTTPS, זה עובד).

אינה עוצרת את ה-COMMIT שאחריה, ולכן `batch` עבר לשימוש בסוג הבקשה `batch`
עם תנאים בין השלבים. בלי זה, מחיקת חשבון שנכשלת באמצע הייתה משאירה חשבון חצי מחוק.

## מגבלות האירוח חסר-המצב

- **מגבלת הקצב שמורה בזיכרון המופע.** פונקציה מקבלת מופעים מקבילים, ולכן המגבלה
  רופפת יותר מאשר בשרת אחד. היא עוצרת שימוש לרעה גס, לא תוקף נחוש.
  פריט מתועד ב-`docs/STATUS.md`.
- **אין תהליך שנשאר דלוק,** ולכן אין משימות רקע. ניקוי הסשנים שפג תוקפם רץ פעם
  אחת לכל מופע, בבקשה הראשונה שלו.
- **קריאה ראשונה אחרי שקט** מקבלת cold start של מאות אלפיות שנייה. לא הרדמה
  של דקה כמו בשירות חינמי עם מכונה.

## מסלולים אחרים, אם המצב משתנה

**שרת רגיל שרץ כל הזמן** (Render, Railway, מכונה וירטואלית): `Dockerfile`,
`render.yaml` ו-`railway.json` עדיין נכונים ועובדים. השרת מגיש את האתר,
האפליקציה וה-API מאותה כתובת. שם מגבלת הקצב מדויקת ואין cold start.

**שרת עם דיסק מתמיד:** `DB_DRIVER=sqlite` ו-`SQLITE_PATH=/data/coach.db`, עם
volume ממופה ל-`/data`. אפס שינוי בקוד - זה בדיוק מה שהדרייבר המקומי עושה.

**מכונה חינמית לתמיד:** Oracle Cloud Always Free נותן מכונה שנשארת דלוקה עם דיסק
אמיתי. בתמורה אתם מתחזקים שרת Linux, והמכונה עשויה להיות מוחזרת אם היא יושבת
בלי שימוש.

## גיבוי

```
curl -s https://personal-coach-beige.vercel.app/api/account/export -H "cookie: <סשן>" > backup.json
```

זה מייצא נתוני משתמש אחד. לגיבוי מלא של המסד כדאי להשתמש בכלי של Turso.
