# ארכיטקטורה והחלטות

## בחירת הסטאק, ולמה לא Next.js ו-PostgreSQL

הבקשה ציינה העדפה ל-TypeScript, React/Next.js ו-PostgreSQL, "או חלופה מנומקת". הנימוק:

סביבת הפיתוח שבה נבנתה האפליקציה היא **בלי גישת רשת להתקנת חבילות**, ובלי שרת PostgreSQL פעיל.
בנסיבות האלה, פרויקט Next.js + Prisma היה נכתב אבל לא היה עולה, לא היה נבדק ולא היה נבנה.
הבקשה גם דרשה מפורשות לבדוק את התוצאה ולא להצהיר על מוכנות בלי בדיקה.

לכן נבחרה חלופה שעומדת בשתי הדרישות:

| רכיב | הבחירה | למה |
|---|---|---|
| שפה | TypeScript | כנדרש. מורץ ישירות ב-Node 22 בהפשטת טיפוסים, בלי שלב build |
| שרת | מודול `http` מובנה | אפס תלויות, עולה ונבדק כאן בפועל |
| מסד | SQLite דרך `node:sqlite` | מובנה ב-Node 22, התמדה אמיתית, בלי התקנה |
| ממשק | SPA בוונילה, RTL, PWA | בלי bundler. נבדק ברינדור אמיתי בבדיקות |
| AI | ממשק ספק מוחלף | ברירת מחדל: ניסוח מקומי. בלי תלות בספק יחיד |

התוצאה: 84 בדיקות עוברות, השרת עולה, המסלול המלא עובד - במקום קוד שנראה נכון ולא רץ.

### מה כן נדרש כדי לעבור ל-React/Next.js
מנוע הכללים ב-`src/domain` **אינו תלוי בשרת ובממשק**: טיפוסים, פונקציות טהורות, אפס IO.
אפשר להעביר אותו as-is לפרויקט Next.js ולעטוף ב-Route Handlers. הממשק הוא מה שייכתב מחדש.

### מה נדרש כדי לעבור ל-PostgreSQL
כל גישה לנתונים עוברת דרך `src/db/repo.ts`. אין SQL מחוץ לקובץ הזה.
המעבר דורש: מימוש חלופי של אותן פונקציות, והתאמות הסכמה שרשומות בסוף
`src/db/migrations/001_init.sql` (TEXT→TIMESTAMPTZ, INTEGER→BOOLEAN, data_json→JSONB,
והוספת Row Level Security בנוסף לאכיפה בשכבת ה-repository).
`DB_DRIVER=postgres` מוגדר כבר כמשתנה סביבה ונכשל בהודעה מפורשת, כדי שלא ייראה כאילו הוא עובד.

## ניתוב: אתר ואפליקציה תחת אותו דומיין

```
/                 -> www/index.html          אתר התדמית
/download         -> www/download.html       (גם בלי סיומת .html)
/transparency     -> www/transparency.html
/privacy          -> www/privacy.html
/app  /app/*      -> public/index.html       מסגרת האפליקציה; ניווט פנימי ב-hash
/downloads/<file> -> downloads/<file>        רק .apk .aab .ipa .zip, כהורדה
/styles.css /app.js /icons/* /manifest /sw.js -> public/
נתיב לא מוכר      -> עמוד הבית של האתר
```

ה-manifest מגדיר `start_url` ו-`scope` של `/app`, כך שהתקנה מהדפדפן פותחת את האפליקציה
ולא את האתר. הניווט הפנימי באפליקציה מבוסס hash (`/app#/week`), ולכן אין צורך בשכתוב
נתיבים בשרת ואין נתיבים שבורים ברענון.

```
┌─────────────────────────────────────────┐
│ www/     אתר תדמית סטטי                  │  בלי גישה לנתוני משתמשים
├─────────────────────────────────────────┤
│ public/  ממשק: PWA, RTL, בלי ספריות      │  אינו מקור אמת להרשאות או לבטיחות

┌───────────────────▼─────────────────────┐

└───────────────────┬─────────────────────┘
          ┌─────────┴──────────┐
┌─────────▼────────┐  ┌────────▼─────────┐
│ src/domain/      │  │ src/ai/          │
│ מנוע הכללים       │  │ ניסוח בלבד        │
│ פונקציות טהורות   │  │ אופציונלי         │
└─────────┬────────┘  └──────────────────┘
          │ קורא תוכן
┌─────────▼────────┐      ┌──────────────┐
```

**כיוון התלות חד־כיווני:** `domain` אינו מייבא מ-`server`, מ-`db` או מ-`ai`.
זה מה שמאפשר לבדוק את כל הלוגיקה המקצועית בלי שרת ובלי מסד.

## החלטות שראוי להכיר

**שמירה אוטומטית אמיתית.** כל סט נשמר בקריאה נפרדת לשרת. אם הרשת נופלת, הסט נכנס לתור
ב-`localStorage` ונשלח כשהחיבור חוזר (`flushQueue`). ה-Service Worker **אינו** שומר קריאות API
במטמון - נתוני בריאות לא נשמרים במטמון הדפדפן.

**גרסאות תוכנית.** כל תוכנית נשמרת עם `version` ו-`status`. שינוי מהותי (מספר אימונים שונה,
או שלושה תרגילים ומעלה שהוחלפו) נשמר כ-`pending_approval` ואינו מחליף את התוכנית הפעילה
עד שהמשתמש מאשר. ה-diff מציג מה משתנה **ומדוע**, עם מזהה הכלל.

**שכבת AI שלא יכולה להזיק.** `src/ai/provider.ts` מקבל `facts` - מספרים וקטגוריות שחושבו
במנוע הכללים - ומחזיר טקסט. הוא לא מקבל שם, אימייל, מזהה משתמש או טקסט רפואי חופשי.
כשל, timeout או מפתח חסר מחזירים את הניסוח המקומי, והמוצר ממשיך לעבוד.
בלי `consent_ai_at` שום דבר לא יוצא מהשרת.

**שני מסלולי כניסה.** חשבון עם אימייל וסיסמה, או כניסה מהירה עם שם חופשי וקוד גישה משותף.
בכניסה מהירה נגזר מזהה יציב מהשם (sha256 של השם המנורמל), כך שאותו שם מחזיר תמיד את אותו
חשבון ושמות שונים מקבלים חשבונות מופרדים לחלוטין. הסיסמה שנשמרת לחשבון כזה היא אקראית
ואינה בשימוש - הכניסה נעשית דרך הקוד. **הקוד משותף ולכן אינו הוכחת זהות**: מי שמכיר אותו
יכול להיכנס בכל שם. זה מתועד במסך הכניסה, בעמוד הפרטיות וב-`docs/STATUS.md`,
ומכובה ב-`QUICK_ACCESS=off`.

**הגבלת קצב.** `src/server/rate-limit.ts` - מונים בזיכרון לכל כתובת ולכל נתיב.
הרשמה 15 לשעה, התחברות וכניסה מהירה 10 ל-15 דקות. התחברות שהצליחה מאפסת את המונה.
כיוון שקוד הגישה משותף, ההגבלה הזו היא ההגנה המרכזית מפני ניחוש אוטומטי.

**הרשאות.** עוגיית סשן HttpOnly; במסד נשמר רק גיבוב של הטוקן עם `SESSION_SECRET`.
סיסמאות: scrypt עם מלח ייחודי. כל שאילתה על נתוני משתמש מסוננת ב-SQL לפי `user_id` -
גם קריאה וגם כתיבה. ניסיון גישה לאימון של אחר מחזיר 404 ולא 403, כדי לא לחשוף קיום.

**יומן ללא נתוני בריאות.** `audit_log` רושם פעולות טכניות בלבד (`plan.generated`,
`workout.completed`). אין בו משקל, מגבלות, אלרגנים או תוכן תזונתי.

**מה שאינו נאסף.** אין בטיפוסים שדה לגזע או למוצא, ואין מקום להזין אותו.
התאמות תרבותיות באות מהעדפות שהמשתמש בוחר בעצמו.

## PWA

- `manifest.webmanifest`: `display: standalone`, `dir: rtl`, אייקון `maskable` לאנדרואיד,
  קיצורי דרך.
- `sw.js`: מסגרת האפליקציה ב-cache-first עם רענון ברקע; API ב-network-only;
  בקשות שאינן GET לא עוברות במטמון כלל.
- iOS: `apple-mobile-web-app-capable`, `apple-touch-icon`, שורת מצב שקופה,
  שלושה מסכי פתיחה, `viewport-fit=cover` עם `env(safe-area-inset-*)` בכל רכיב קבוע,
  ושדות קלט ב-16px כדי למנוע זום אוטומטי בספארי.
- העיצוב: מערכת טוקנים ב-CSS, מצב כהה ובהיר, מאפיינים לוגיים (`margin-inline`) כדי
  ש-RTL יעבוד נכון, אזורי מגע של 44px ומעלה, וכיבוד `prefers-reduced-motion`.
