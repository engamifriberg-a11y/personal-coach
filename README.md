# מאמן אישי - אתר ואפליקציית אימונים וליווי תזונתי

אתר עם אפליקציה עובדת (לא אפיון): תוכניות אימון אישיות, הדגמות תרגילים, ליווי תזונתי
ומעקב התקדמות. בעברית, RTL, מותאם קודם כל לטלפון, ומותקן על הטלפון כאפליקציה (PWA).

```
/              אתר התדמית - מה המוצר, איך זה עובד, שקיפות
/download      הורדה והתקנה לכל פלטפורמה, ומצב קובץ ההתקנה
/transparency  המקורות המקצועיים ומה שעוד לא נבדק
/privacy       מה נשמר ואיך
/app           האפליקציה עצמה (PWA, ניווט פנימי ב-hash)
/api/*          ה-API
```

**מה היא לא:** אבחון, טיפול או ייעוץ רפואי. הגרסה הראשונה מיועדת לבני 18 ומעלה.
חלק מהכללים המקצועיים מסומנים "ממתין לביקורת מקצועית" ואינם מוצגים כמאושרים - ראו `docs/STATUS.md`.

## הרצה מקומית

דרישה אחת: **Node.js 22.6 ואילך**. אין תלויות npm להתקנה.

```bash
cp .env.example .env
# ליצירת סוד סשן:
node -e "console.log(require('crypto').randomBytes(32).toString('hex'))"
# להדביק בשדה SESSION_SECRET בתוך .env

npm run migrate          # יצירת מסד הנתונים והרצת מיגרציות
npm run seed             # יצירת חשבון מנהל תוכן
npm run seed -- --demo   # בנוסף: חשבון דמו עם פרופיל, תוכנית ותפריט
npm start                # האתר: http://localhost:3000  ·  האפליקציה: /app
```

| פקודה | מה היא עושה |
|---|---|
| `npm start` | מריץ את השרת |
| `npm run dev` | אותו דבר עם טעינה מחדש אוטומטית |
| `npm run migrate` | מיגרציות (בטוח להרצה חוזרת) |
| `npm run seed` | חשבון מנהל; עם `-- --demo` גם חשבון דמו |
| `npm test` | כל הבדיקות (84 בדיקות) |
| `npm run typecheck` | בדיקת טיפוסים. דורשת `npm install` חד־פעמי |

חשבונות לאחר `seed`:

- מנהל תוכן: `admin@example.com` / `Admin!2345` - **יש לשנות סיסמה לפני שימוש אמיתי**
- דמו (רק עם `--demo`): `demo@demo.local` / `Demo!12345`

חשבונות דמו מסומנים במסד בעמודה `is_demo=1` ומופרדים מנתוני משתמש אמיתי.

### כניסה מהירה

מסך הכניסה מציע שני מסלולים. ברירת המחדל היא **כניסה מהירה**: שם חופשי + קוד גישה משותף.

```
QUICK_ACCESS=on            # on / off
ACCESS_CODE=<הקוד שלך>     # הקוד שמוזן במסך הכניסה
```

אין קוד ברירת מחדל בקוד המקור. בלי `ACCESS_CODE` המסלול כבוי לגמרי, והאפליקציה
עובדת רק עם חשבון אימייל וסיסמה. בפריסה מגדירים את הקוד כמשתנה סביבה אצל המארח,
ולא בקובץ שנכנס לגיט.

כל שם מקבל חשבון נפרד, והנתונים מופרדים בין השמות. אותו שם מחזיר את אותם נתונים.

> **מגבלת אבטחה שחייבת להיות גלויה:** הקוד משותף, ולכן מי שמכיר אותו יכול להיכנס בכל שם -
> כולל שם שמישהו אחר השתמש בו. זה מתאים לקבוצה שסומכת זה על זה, ולא לשימוש ציבורי.
> לשימוש אמיתי יש להעביר ל-`QUICK_ACCESS=off` ולהשתמש בחשבון עם אימייל וסיסמה.
> נתיבי האימות מוגבלים בקצב (10 ניסיונות ל-15 דקות לכל כתובת), וזו ההגנה המרכזית
> מפני ניחוש אוטומטי של הקוד.

## התקנה על הטלפון

האפליקציה היא PWA: נפתחת בדפדפן ומותקנת כאפליקציה עם אייקון, מסך פתיחה ומצב מלא בלי שורת כתובת.

**אנדרואיד (Chrome):** נכנסים לכתובת → מופיע באנר "התקנה", או תפריט ⋮ → "התקנת אפליקציה".
האפליקציה מקבלת אייקון maskable, מסך פתיחה וקיצורי דרך (אימון / תזונה / מעקב).

**אייפון ואייפד (Safari):** כפתור השיתוף → "הוספה למסך הבית". האפליקציה תומכת ב:
`apple-mobile-web-app-capable`, אייקון `apple-touch-icon`, שורת מצב שקופה, מסכי פתיחה בשלוש רזולוציות,
התאמה ל-`safe-area` של הנאטץ' ושל הכיסוי התחתון, ושדות קלט ב-16px שמונעים זום אוטומטי.

להתקנה אמיתית נדרש HTTPS (Service Worker אינו עובד מעל HTTP, מלבד `localhost`).

**אריזה ל-APK/AAB בחנות:** התצורה מוכנה תחת `packaging/` (Bubblewrap ל-TWA, או Capacitor).
הבנייה עצמה דורשת Android SDK/Xcode ואינה נכללת כאן - ראו `packaging/README.md`.

**קובץ התקנה באתר:** כל קובץ `.apk` / `.aab` / `.ipa` / `.zip` שיונח בתיקיית `downloads/`
יופיע אוטומטית בעמוד `/download` ככפתור הורדה אמיתי, עם שם, גודל ותאריך. כל עוד התיקייה
ריקה, העמוד אומר במפורש שאין קובץ - ולא מוצג קישור מומצא.

## עקרונות שמוטבעים בקוד

1. **מנוע כללים מופרד מ-AI.** התוכנית, העומסים והספים נקבעים ב-`src/domain` בלבד.
   שכבת ה-AI מקבלת עובדות מחושבות ומנסחת טקסט. היא אינה יכולה לעקוף בטיחות,
   ובלי ספק AI המוצר עובד במלואו.
2. **אין סף מספרי בלי מקור.** כל כלל רשום ב-`src/domain/sources.ts` עם מקור, גרסה ותאריך בדיקה.
   כלל שאינו נשען על מקור מצוטט מסומן `pending_review`, מוצג כך בממשק, ומופיע ב-`docs/STATUS.md`.
3. **אין קישורים מומצאים.** אין בקוד אף קישור לסרטון. מדיה מוזנת דרך פאנל הניהול עם מקור,
   בעלים ורישיון, ומוצגת רק אחרי סימון `verified`. בלי מדיה מאומתת מוצגות הוראות כתובות,
   ולא נגן שבור.
4. **אין דיוק מדומה.** אומדן האנרגיה מוצג כטווח עם הנחות החישוב. דילוג על נתון המין מרחיב
   את הטווח במקום להמציא ערך.
5. **גזע ומוצא אינם נאספים ואינם קיימים בטיפוסים.** התאמות תרבותיות נגזרות רק מהעדפות
   שהמשתמש מציין בעצמו (כשרות, טבעונות, אלרגנים).
6. **בידוד נתונים בצד השרת.** כל שאילתה מסוננת לפי `user_id`; הרשאות מנהל נאכפות בשרת.
7. **הסכמה לפני שמירת נתוני בריאות**, ייצוא מלא ומחיקת חשבון אמיתית.

## פריסה

המדריך המלא: **`docs/DEPLOY.md`**. בקצרה, הפריסה מחולקת לשניים:

| חתיכה | מארח | למה |
|---|---|---|
| האתר (`/`, `/download`, `/transparency`, `/privacy`) | Vercel | קבצים סטטיים, CDN והדומיין |
| האפליקציה (`/app` + `/api/*`) | Railway / Render / Fly | צריך תהליך שרץ קבוע ודיסק מתמיד |

אפשר גם להעלות את שניהם למארח אחד - השרת מגיש את שניהם.

**למה לא הכול ב-Vercel:** אירוח ללא שרת מוחק את מערכת הקבצים בין בקשות,
והאפליקציה כותבת ל-SQLite על הדיסק. בלי דיסק מתמיד חשבונות ואימונים נעלמים.

בפרויקט כבר יש `Dockerfile`, `railway.json`, `render.yaml` ו-`vercel.json`.
מה שחובה לוודא בפריסה:

- **volume ממופה ל-`/data`** - בלעדיו כל פריסה מחדש מאפסת את המסד.
- `SESSION_SECRET` ייחודי, ו-`NODE_ENV=production` כדי שהעוגייה תסומן `Secure`.
- `TRUST_PROXY=1` מאחורי proxy, אחרת מגבלת הקצב רואה את כולם כאותה כתובת.
- **עותק אחד בלבד** (`numReplicas: 1`): SQLite ומגבלת הקצב אינם משותפים בין עותקים.
- `npm run seed` פעם אחת ליצירת חשבון המנהל, ומיד לשנות את הסיסמה.
- גיבוי לקובץ ה-SQLite.

**לא נפרס כאן בפועל ואין כתובת אתר** - התצורה מוכנה וההוראות מדויקות.
